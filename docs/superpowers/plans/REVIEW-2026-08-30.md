## Critical findings

### C1 — WS-B: `--network none` bricks every container run
`hasEgressGrants` is computed from `database.grants`, which is now always `[]` (nothing seeds grants) → every agent gets `--network none` → the Codex CLI inside the container cannot reach the model API. In Gemini mode `config.ts:76` points the container at `http://host.docker.internal:<port>/api/adapter` via `--add-host`; cutting the network kills the adapter callback. **No agent can complete any run.** Also fails WS-B's own Task 5 test (asserts `hasEgressGrants === undefined`; it computes `false`).
**Fix:** seed a standing `network:egress` grant for the model-API host at agent creation, AND gate `--network none` behind an explicit config flag until grants are seeded. Delete the dead `undefined` branch and its test.

### C2 — WS-B: "fail closed" is false; it is post-hoc detection
`onStep` is invoked only from `parseCodexEventLine` on `item.completed` (`codex-runner.ts:63-107`) — the command detail even carries `(exit N)`. **The command already ran inside the container before the guard sees it.** The "block" suppresses trace recording and fails the run afterwards; the exfiltration already happened. Worse: an agent holding one grant for `api.example.com` has unrestricted bridge networking to every host. A judge who reads the code will find this in minutes, and it undercuts the headline demo moment.
**Fix (choose one):** (a) implement the real proxy from [prior-art upgrade #1](../specs/2026-08-30-prior-art-and-upgrades.md) — but see C8 first; or (b) reword honestly: "Phase 1 — detection fast path + zero-grant network cutoff; per-host enforcement arrives with the proxy." Change the event title from "Egress blocked before execution" to "Egress violation detected; run failed closed." Honesty here scores better than an overclaim judges puncture.

### C3 — WS-C: codegraff is AGPLv3, not Apache-2.0 — do not vendor
The plan vendors `packages/diffs` believing `package.json`'s `"license": "Apache-2.0"`. The **root LICENSE** (which governs; no subpackage LICENSE exists — 404 confirmed) is a *modified GNU AGPLv3* reserving commercial rights to two named individuals; everyone else gets plain AGPLv3 with Section 13 network-use copyleft intact. Vendoring into a network-facing demo triggers source-disclosure obligations on this repo. The `package.json` field is simply wrong metadata.
**Fix:** swap to **`react-diff-view` (MIT)** + **`jsdiff` (BSD-3-Clause)** — both confirmed React 18 + Vite compatible, jsdiff actively maintained. Strip "Apache-2.0" from Task 4/5 commit messages and per-file attribution headers.

### C4 — WS-A: `policy.decision` events are never wired into the authz path
The spec requires *every* allow/deny persisted as a `policy.decision` RunEvent. Task 4 creates `recordPolicyDecision` and unit-tests it, but **no task ever calls it** from the resource-access path. Task 5's own manual verification ("trace shows policy.decision events") would fail. Design hole: the route has no run context and `RunEvent` requires `runId`.
**Fix:** inject `AgentService` (or a recorder callback) into the resource route, resolve the agent by `principalId`, use its active-or-latest run for `runId`, and specify the no-active-run fallback. **This is the demo's hero evidence — without it there is nothing to show in the trace.**

### C5 — WS-A: Task 3 Steps 5–6 are not executable
`createApp(config, service)` is 2-arg (`app.ts:47`); the plan never specifies the new signature for injecting `IdentityService`, and `index.ts` (the only real wiring site) is in no task's Files list. `app.test.ts` has **4 existing `createApp` call sites** using stubbed services — a required third param breaks all four, unmentioned. Step 6 says "adapt to app.test.ts's existing bootstrap for creating an agent" — **no such bootstrap exists**; every test stubs the service.
**Fix:** specify `createApp(config, service, identity?)`, list `index.ts` + the 4 test call-sites, and write the real-stack test harness explicitly (tmpdir config + JsonStore + WorkspaceManager + fake runner + both services sharing one store).

### C6 — WS-D Task 1 and WS-E Task 1 are redundant AND destructive
Both re-declare types that now exist (duplicate-identifier compile errors) and both replace `Database`/`emptyDatabase`/`migrateDatabase` wholesale — **deleting WS-A's working `migrateV3ToV4`**, its principal/resource seeding, and its passing test. Their TDD "expected: FAIL" steps will silently pass, hiding the staleness.
**Fix:** replace both Task 1s with verification-only steps. Do not touch `types.ts`/`store.ts`/`store.test.ts`.

### C7 — WS-D: mid-run degrade may be impossible
`turn.completed` exists and carries usage, but nothing establishes it fires **more than once** per `codex exec`. If it fires once at run end, `onUsage` is effectively an end-of-run callback: the breaker cannot trip mid-run, and the override is cleared moments after being set — so `budget.degraded` fires but changes no actual model call. The plan's own tests can't catch this (FakeRunner injects `onUsage` twice synthetically).
**Fix:** empirically count `turn.completed` occurrences in a real `codex exec --json` run with a multi-tool prompt. If always 1, either move the breaker to session-cumulative (degrade persists into the *next* message) or document it honestly as end-of-run.

### C8 — Docker `--internal` + `host.docker.internal` is platform-dependent
Load-bearing for the WS-B proxy upgrade. Docker docs permit gateway-IP communication on internal networks, so Linux + `--add-host=host-gateway` should work. **Docker Desktop macOS: unverified** (vpnkit, not plain gateway routing). **Colima: already flaky** without `--internal` (multiple open issues). **Rootless Podman: documented broken** — "an internal network is not routed anywhere and thus cannot reach the host."
**Fix:** test this exact combination on the demo machine's actual engine before depending on it. Fallback: sidecar proxy *container* on the same internal network (reachable by container name), not a host proxy.

## Important findings

- **WS-B:** bare-word matches (`git fetch`, `npm install node-fetch`) yield `host: null` → unconditional deny + quarantine strike, a regression from today's recoverable HITL approval. `message`-type steps count strikes too, so an agent merely *mentioning* a URL accumulates them. → Fall through to HITL for `host: null`, exclude `message` steps from strikes.
- **WS-B:** first-URL-only extraction is a one-line bypass — `curl https://allowed.com/x https://evil.net/y` evaluates only the first host. → Extract all hosts, deny if any lacks a grant.
- **WS-A:** Task 4 tests reference a `store` variable that doesn't exist (`makeService()` returns only the service; `AgentService.store` is private). → Return `{ service, store }`.
- **WS-A:** `grant.created`/`grant.revoked`/`grant.expired` are added as types but never emitted by any task. → Emit in `createGrant`/`revokeGrant`, or descope explicitly.
- **WS-A:** route snippets use `request.body as {...}` casts; `app.ts` validates exclusively with zod. → Define zod schemas.
- **WS-C:** `MAX_SNAPSHOT_FILES` (500) truncation makes a missing file indistinguishable from "never existed" — on deny, `restore()` **unlinks a pre-existing file the operator never asked to remove**. → Treat snapshot-miss as "unknown: do not diff, do not delete."
- **WS-D:** `clearModelOverride()` is unconditional and process-global — an unrelated run finishing wipes another run's active degrade. → Gate with `if (degradedModel)`.
- **WS-D:** replay reuses the agent's live session and resumes its existing `codexThreadId` — inherits unrelated conversation history, pollutes the user's visible chat, and throws raw `HttpError(409)` if the agent is busy (uncaught). → Fresh session for replay; catch `HttpError`.
- **WS-D:** racy "find the blocked run" fallback (`sort(createdAt).at(0)`) can attribute the wrong run under concurrency.
