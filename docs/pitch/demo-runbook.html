Open blocker — fix before submitting

npm run check exits 1 even though every test passes. An unhandled RunCancelledError escapes container-codex-runner-pause.test.ts — a cancelled run's promise is never awaited or caught, so Vitest reports "Errors 1 error" and fails the run.

This matters because npm run check passing is on the track's own acceptance checklist. A reviewer working that list hits a red on an otherwise green repository. It is a leaked promise in a test, not a containment defect — but fix it before submission, and do not invite judges to run check on stage until you have.

Good news worth saying on stage

Every demo script now asserts its invariants through scripts/demo-assert.mjs and exits non-zero if containment breaks. It is no longer a thing you read — it is a thing that can fail. If the README still says the demos "print observations rather than asserting them", that line is stale and should be corrected before submission.

SECTION 01Fifteen minutes before you present

The biggest risk in a three-minute demo is watching a build or an image pull in silence.

  • Pre-build the server. Every demo:* script builds first. Build once now and the live runs start instantly.
  • Run each demo once, end to end. Caches the container images and proves the invariants hold on today's tree.
  • Start the platform and leave it running. npm run poc → localhost:3000. Never start it on stage.
  • Create the Agent in advance. Already in the list, lifecycle state visible. Creating one live burns twenty seconds on starter-kit CRUD.
  • Terminal font 18pt or larger. Judges read a projector from four metres. This demo is mostly terminal output — it has to be legible.
  • Two windows, no alt-tabbing. Browser left, terminal right, both visible at once.
  • Rehearse with a timer. The usual failure is running long and being cut off before the receipt — which is your best moment.

SECTION 04When it breaks on stage

Work down this ladder without apologising. Recovering calmly reads as competence.

Rung 1 — the container engine is down

demo-escalation.mjs and demo-passport.mjs need no engine and no key. Your best demo is also your most robust one. Say: “engine's not cooperating — here is the authority boundary, which does not need it.”

Rung 2 — the live Agent run hangs on the model

Do not wait. Say: “the provider is slow, which is exactly why containment cannot depend on the model,” and go straight to the escalation demo. It never touches a model API.

Rung 3 — nothing runs

Narrate over a pre-recorded capture and say plainly that it is a recording. Judges forgive a recording; they do not forgive two minutes of silence.

Rung 0 — record the fallback tonight

Capture clean runs of demo-escalation and demo-kill while everything works. Five minutes now, and the worst case stops being catastrophic.

SECTION 05Questions judges will ask

Grounded in what the code does. Where an answer needs checking against your merged branch, it says so.

Isn't this just a firewall?

Lead with the escalation demo, not the network. A firewall would not have stopped the actual attack — the agent never touched the network boundary; it asked the control plane for a wider grant, from inside.

What stops that is an authority model: humans originate authority, agents may only ever pass along less, and capability families are incomparable so network access can never be traded out of storage access.

How did you find the confused-deputy bug?

Be direct: the control plane is reachable from inside an agent container because the model adapter lives there. Once you see that, the cheapest attack is obviously not the wall — it is the door.

demo-escalation.mjs reproduces both the original exploit and the fixed behaviour, so the fix is regression-tested rather than asserted.

What does the receipt actually prove?

Claim it narrowly and you will be believed: the signed receipt authenticates the control plane's recorded termination observations — origin, integrity, internal consistency, and that the step outcomes agree with the containment claim.

It does not claim earlier effects were undone, and offline verification cannot independently recreate the runtime observation. Saying that unprompted is worth more than overclaiming.

Does revoking kill a connection that is already open?

No — and that is precisely why termination exists as a separate path. Revocation stops the next connection. Termination freezes first, then atomically blocks authority and revokes, then kills, then verifies. If a live runtime cannot be frozen, it records that failure and refuses to claim containment.

Your human identity is still a mock.

Agree immediately and draw the line precisely. Human identity is a mock — x-principal-id is unauthenticated. Agent identity is not: it is bound to the containment topology, the proxy strips caller-supplied attestation and stamps the identity itself, and the agent container never holds the server secret.

Production needs an operator IdP and RBAC. The enforcement path above it does not change.

What about DNS or another covert channel?

Contain the claim: HTTP and HTTPS go through the proxy, the internal network removes the direct route, and non-HTTP TCP is refused because it cannot traverse an HTTP proxy. Opaque CONNECT tunnels to the control plane are refused outright — demo-tunnel-bypass.mjs.

If you have not measured DNS on your merged branch, say so. A caught overclaim discounts everything else you said.

Why hostname and not full URL for HTTPS?

CONNECT exposes only the host, so per-path rules need TLS termination. Anthropic's own sandbox-runtime documents the same limit — state of the art, not a shortcut.

How much of this was the starter kit?

Precision reads as confidence. The approval UI, canary tripwire, budget breakers and trace timeline came with the kit. This project added identity, scoped and revocable grants, the authority-attenuation model, the network gate enforced before the socket opens, verified termination, and the signed receipts.

What would you do next?

Have one specific answer: authenticate the operator (the last mock in the identity story), then persist quarantine strikes, which currently reset on restart. Both are named as limitations in the repo — you were tracking them, not discovering them under questioning.
